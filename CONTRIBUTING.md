# Contributing

Thanks for helping improve this project.

## Additions

For feature changes and meaningful improvements, please:

- Open an issue describing the change and why it is needed.
- Include a short reproduction path for bugs when applicable.
- Open a focused pull request once the issue direction is agreed.
- Keep commit messages semantic (for example: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`, `ci:`).

## Development workflow

- Test changes locally before opening a PR.
- Keep PRs focused and small.
- Update docs when user-visible behavior changes.

## Quality bar

Prefer fixes and additions that are:

- Relevant to security/blocklist automation and reliability.
- Well-tested.
- Practical for real-world Linux and macOS environments.

## Commit and PR conventions

- Use semantic commit prefixes: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`, `ci:`.
- PR title should follow the same style.
- Link the issue in your PR body where appropriate (for example: `Closes #123`).
